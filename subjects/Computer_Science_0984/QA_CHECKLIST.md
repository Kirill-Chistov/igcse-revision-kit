# Computer Science — QA Checklist

Run this against any study material before treating it as finished.

## Specification

- [ ] The material names the exact specification points it covers, by official number.
- [ ] Every requirement in those points is actually covered — nothing quietly dropped.
- [ ] Every named item in the point's *Notes and guidance* column is covered; nothing added
      that it does not name.
- [ ] Nothing off-specification is presented as required content, including textbook material
      sitting beside required content.
- [ ] Paper, tier and other course distinctions in `SUBJECT_RULES.md` are respected.

## Correctness

- [ ] Every factual claim, equation, figure and unit is correct.
- [ ] Terminology matches the awarding body's own usage.
- [ ] Definitions are precise enough to earn the mark.

## Usability

- [ ] Understandable by a Year 11 student who has covered the earlier specification points.
- [ ] Difficult ideas are explained, not merely named.
- [ ] Examples and diagrams clarify rather than pad.
- [ ] No enrichment (Level C) — only required content plus minimal bridging.
- [ ] No filler, repetition or textbook throat-clearing.
- [ ] Minimum standard met: no block survives that the student could lose without losing marks
      (`CONTENT_STYLE.md` §2).
- [ ] Where the requirement says *use / write / complete / calculate*, the skill is actually
      practised, not only described.
- [ ] Each required point is taught once, in one representation — never diagram **and**
      equivalent table **and** equivalent prose.

## Computer Science conventions

- [ ] Pseudocode follows the syllabus section 4 conventions; no invented syntax, and no parallel
      Python / Java / VB versions while the classroom language is unconfirmed.
- [ ] Flowchart and logic gate symbols match section 4 exactly; logic circuits are drawn as stated,
      without simplification.
- [ ] Operators, data types, library routines, SQL keywords and standard methods stay inside the
      lists the specification gives.
- [ ] The built topic PDF was opened and every figure rendered correctly.

## Consistency

- [ ] Consistent with other material already in `Computer_Science_0984/` for this subject.
- [ ] Follows `rules/STYLE_GUIDE.md`.
- [ ] Sources used respect `rules/SOURCE_POLICY.md`.

## Repository hygiene

- [ ] Markdown is the canonical version; the topic PDF was rebuilt from it and visually checked.
- [ ] No recap, self-test, answers or checklist sections in `topic.md`, `summary.md` or the PDF.
- [ ] `coverage_checklist.md` and `specification_map.csv` rows for the covered points updated.
